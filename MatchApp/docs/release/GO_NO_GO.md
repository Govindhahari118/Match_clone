# Matree engineering GO / NO-GO report

## Decision semantics

- **Repository GO** means all mandatory code-controlled CI jobs are green on the exact candidate SHA
  and no known repository-controlled P0/P1 is exposed.
- **Production GO** additionally requires the machine-verified external prelaunch gate to pass with
  operator-controlled evidence for the same SHA.

## Current policy

A candidate is **NO-GO** if any of the following is true:

- Android build/unit/lint/release-R8 gate fails;
- Room migration matrix fails;
- Firestore/Storage authorization tests fail;
- Functions lint/build/tests/high-severity production dependency audit fails;
- screen classification, truthfulness, callable-contract or release-candidate scans fail;
- active route has a known P0/P1 defect;
- external prelaunch evidence does not pass for the exact SHA.

A historical green run never certifies a newer commit.

## Repository completion criteria

Before handing to infrastructure/release operations, the exact head must provide:

- release candidate source and green mandatory CI;
- final registered Room migrations;
- server-authoritative API surface;
- Rules/indexes/storage policy;
- feature-flag safe defaults;
- health/readiness endpoints;
- environment/secrets/API/schema/master-data documentation;
- rollback runbook;
- smoke/regression/security evidence generated by CI;
- known-issues/deferred-surface record.

## Production promotion

Run:

`python3 scripts/ci/production_external_gate.py --evidence <operator-file> --sha <exact-sha> --mode prelaunch`

Only a passing result plus exact-head green repository CI permits production promotion. Controlled
rollout/post-rollout evidence is required for the subsequent `--mode full` gate.
